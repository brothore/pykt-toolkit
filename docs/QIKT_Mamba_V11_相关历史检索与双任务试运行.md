# V11：相关历史检索与冻结负载双任务试运行

2026-11-09，启动前登记。V6题目/简单历史统计分支仍在执行，V8/V9/V10的已有预测分析已经说明“提高总体”“缩小std”和“修复range”并不等价。新假设：Mamba共享状态及KC平均统计可能遗漏与当前题相关的具体历史题目、响应及时间尺度。检索分支保留这些关系信息，不能预先认定它有效。

## 科学方案

冻结同一原baseline，在当前题embedding与历史题embedding之间做64维因果attention，历史value包含题目与响应embedding，再产生有界残差。当前位置t只能读取k<t的响应；当前题已知，当前/未来响应不可见。原上下文200，窗口内计算，不增加V10那样的额外跨窗口状态。

|方向|新增信息或保护|最多三轮|
|---|---|---|
|T0|仅题目内容相似度检索已答历史|lr=.001/scale=.25；.003/.5；.0003/.5|
|T1|T0＋同KC历史attention bias=2|同上|
|T2|同KC检索＋全窗口/最近32位置两尺度读出|同上|
|T3|T2＋对冻结原baseline的KL=1|同上|

四方向最多12轮，首个普通联合点候选记录暂停；不自动追加seed/fold/Peiyou。新增分支dropout=.1，仅该分支在训练启用，原主干持续eval且权重不更新。原生BCE、选模和早停不变。不能把attention收益归给单一信息因素，需比较同轮对照；小残差与KL不保证AUC保持。

仍为nips_task34/QIKT-Mamba/public_mamba/fold0/seed42，primary773、ddof=0；实质门槛为std/range各降≥1%、std区间上界<0、整体/宏均值、弱10/20%、自身尾10/20%、强25%均值保护，另报个体退化。正式windowauclate_mean缺失时明确保留。新类先做严格因果、冻结、训练/推理配置重建测试，再用真实CUDA数据核对零残差预测及一步冻结更新。

## 双任务资源试运行

旧实测针对完整主干；V6冻结后普通epoch约24–26秒，不能把旧单并发推荐当成新负载最优。V6/V7原通道保持原源码和旧锁；本批新增独立第二通道，最多同时1个新任务，与旧通道最多1个任务并行。tsp逻辑槽位只容纳等待控制器，不等于物理GPU并发。

新增任务准入：现有GPU进程必须是已登记V6/V7运行时且最多1个，空闲显存≥6GiB，容器硬限额余量≥6GiB；预算新任务约≤3GiB GPU及≤2GiB主存，保留余量。实际峰值持续采样，估计不是已测峰值。容器内存限制80GiB，必须同时看cgroup使用量，不能只看主机MemAvailable。

记录双任务前后训练epoch、窗口分片速度、总完成时间、利用率与GPU/cgroup峰值。并行是有界试探，不宣称已知最佳；不能只根据利用率或占满显存宣布提速。若争用不划算，由主agent请求新增任务安全停止并核对恢复状态，旧任务不动。

旧通道在家族切换时要求GPU空闲：若它被新增通道挡住，新任务在完整epoch或窗口64批检查点让出并自动续接，确保旧通道不被饿死；小的原生片段导出以整分区重做，不称精确分片恢复。最多12次有因记录的交接，不作无限失败重试。新任务失败如无主动交接原因则直接失败，不掩盖异常。发现未登记GPU上下文或资源压力，只处理自己的新任务，不停止无关进程。
