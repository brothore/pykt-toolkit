# V5：保留原批次顺序的完整序列排序梯度

2026-11-08登记，正式GPU实验尚未开始。V4五方向13轮均完成，无联合候选；不回写其方案/结果。

## 假设与本次修正

V4完整UID分组对照Q0本身使std增加.000843428、range增加.012612481；排序部分相对Q0有局部改善，却没有超过原baseline。不能把这简单归因于排序无效。Q0同时改变UID分组、批次大小及顺序，可能改变梯度噪声/优化路径，具体原因未被独立测量。

源码核查发现原生`init_dataset4train`使用`DataLoader(curtrain,batch_size=...)`，默认不shuffle。此前将原加载方式称为随机/IID不准确。本版复用原sampler及generator，不创建新的随机顺序；原生BCE、多头辅助项、优化器、选模及早停均不变。

每epoch先用当前模型eval模式在**训练折**原计分片段上预测，按完整UID计算logistic或平滑AUC风险对各位置logit的解析梯度。随后在原批次上用固定梯度、anchor概率和每UID常数构成一阶代理。缓存操作前后恢复Python/NumPy/Torch/CUDA及loader/sampler生成器状态，避免额外遍历改变训练顺序或dropout随机轨迹。它是epoch-lag近似，不是当前train-mode真实完整AUC损失，不是OOF教师，也不是按验证真实AUC加权。

代理项对logit偏移裁到±1；梯度对当前模型在裁剪区域内传播。代理值可能不等于非负风险，不能汇报成真实AUC。归一使用“epoch批次数/可排序训练UID数”，使固定logit时整个epoch的平均梯度对应序列宏风险；不假设原加载器IID。单类别序列不参与排序，仍参与原BCE。

## 本批方向与预算

共同为nips_task34/QIKT-Mamba/public_mamba/fold0/seed42、名义batch32、原生切片覆盖和上下文。补齐训练覆盖内的跨切片正负对，不补造被预处理丢弃的尾部，不让模型获得无限历史。

|方向|实现|最多轮次与系数|目的|
|---|---|---|---|
|G0|仅片段索引包装、原sampler/generator、原损失|1轮，rank=0，不做anchor额外遍历|核查包装是否改变结果；实际差值报告，不预先宣称完全相同|
|G1|完整UID logistic风险梯度缓存|rank=.002/.01/.03，trust radius=1|保留大错序梯度并避开V4分组变化|
|G2|完整UID平滑风险梯度缓存|rank=.03/.1/.3，sigmoid((负−正logit)/.5)，radius=1|集中于排序边界，限制巨大错序主导|
|G3|G2＋训练类别支持权重|同G2；minority/(minority+5)归一后裁[.25,1.5]|削弱统计支持极少的排序信号；不称已识别可靠可弥补缺口|

共最多10轮。每方向首次初步联合候选即记录暂停，不自动加seed/fold/Peiyou。G1–G3依赖G0成功完成评估；若G0未复现原baseline，需明确这一偏差，后续仍必须超过原baseline，不能只超过一个变弱的控制。

这是对跨切片排序分支的有界修正；若完成本批仍没有实质信号，不再沿这一分支无限改系数，转而根据证据研究信息缺口或合规OOF补充分支。
